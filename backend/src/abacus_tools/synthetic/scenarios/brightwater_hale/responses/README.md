# Recorded fake-model responses (F-04-T19, F-04-T25; F-04.26)

One JSON file per response, read by `responses.install(fake)`:

```json
{"document": "northwind_trial_balance", "prompt_ref": "evidence.screen@v0", "content_sha256": "<64 hex>", "response": {"action": "..."}}
```

- `content_sha256` is the SHA-256 of a scenario document (`documents.py`) that the prompt input names, or of the rendered input itself. `document` names that document for people; the loader reads only the other three keys.
- `response` is the model's JSON output, or a string. It must parse as the prompt's output schema.
- These are scenario data, written by hand from the scenario documents and never generated by a model.
- Each citation resolves to one of the document's fixed regions (a page rectangle or a sheet cell) and is verified by code (`tests/unit/scenarios/test_scenario_documents.py`), except the one planted unsupported value, `responses.PLANTED_UNSUPPORTED`. That is what makes SHL-10c and SHL-09e show "Uncited".
- A matcher response names its request `R1`: whoever replays the inbox (the loader's later slices) offers the document's own request first.
