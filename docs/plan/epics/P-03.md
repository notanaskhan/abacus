## 3. Features & user stories

Invariants are chapter 01's: **INV-1** the agent never decides; **INV-2** citations shown are verified; **INV-3** walls hold (404, no counts); **INV-4** portal scopes are isolated; **INV-5** attribution is correct. Clock: Mon 14 Sep 2026, 9:24 AM CT (E0); SHL-07 renders at 9:41 AM.

### F1 · Citation v2 as a first-class, verified record (C4 core)

*As Hannah Leclerc, I want every cited value to point at a record the system verified, so that I judge the work, not the agent's word.*

- **AC1.1** *Given* the screener cites page 3 of a Harborline statement with a quote, *when* its handoff is recorded, *then* one `citations` row is written (`kind=document_text`, `created_by_kind=agent`, `created_by_run_id` set), `quote_sha256` is the hash of the words read from the word layer inside the resolved bbox, and the quote text itself is **not** stored (ADR P-48; INV-2).
- **AC1.2** *Given* a citation to page 9 of a 3-page file, a bbox with no words, a quote absent from the page, or a value that differs from the cell, *then* the row is stored `verified=false` with `verification_reason ∈ {page_not_found, bbox_mismatch, quote_not_found, value_mismatch}` and every reader shows it as "Unverified", never as fact (ADR-066).
- **AC1.3** *Given* a valid quote whose bbox cannot be resolved (multi-page or rotated text), *then* the citation is still verified on page text and highlights by quote search; it is never failed only for a missing bbox (chapter 05 §5.3.10).
- **AC1.4** *Given* any attempt to UPDATE or DELETE a `citations` or `citation_events` row, *then* the database rejects it for every role (ADR-004 pattern, insert-only).
- **AC1.5** *Given* the citations of an engagement Lena Park is walled from, *when* Lena calls `GET /v1/citations/{id}` or lists a stack containing one, *then* the single read answers 404 and the list omits it with no hidden count (DEC-43; INV-3). *Given* a client principal, *then* every C4 citation route answers 403 (INV-4; chapter 03: clients never see citations).

### F4 · Masked PII and logged reveal (SHL-08c)

*As Samuel Ito, I want to see a full SSN only when I need it, on the record, so that the firm can prove who saw it.*

- **AC4.1** *Given* the seeded W-2 with "000-00-6081" under the box-a label, *when* it is processed, *then* a `pii_regions` row (`kind=ssn`, `last4=6081`, sealed value) exists. Label-anchored matches are masked even when the number fails SSN validity rules (seed values are deliberately fictional); unlabelled matches must pass validity and checksum rules (§4.4).
- **AC4.2** *Given* any page image served by any route, *then* the pixels inside every detected region are opaque (never blurred or transparent); an unmasked rendition is never generated or stored. *Given* a preview made before masking existed, *then* the route answers 409 `preview_outdated` until the backfill re-renders it.

### 4.4 Detection and masking rules (code, never a model)

- **Label-anchored** (masked even if the number fails validity, because seeds use fictional values): `\d{3}-\d{2}-\d{4}` or 9 digits within the same line or the box above/left of labels such as "social security number", "SSN", "recipient's TIN", "taxpayer identification number", "ITIN"; `\d{2}-\d{7}` near "EIN", "employer identification number", "payer's TIN"; account numbers near "account number"; dates near "date of birth"/"DOB".
- **Unlabelled** matches need validity: SSN area not 000/666/9xx, group ≠ 00, serial ≠ 0000; ITIN 9xx with the IRS group ranges; EIN with a valid campus prefix; routing numbers pass the ABA checksum.
- **Masks**: opaque fill in the page background colour, padded 2 px, burned into the PNG in the isolated child; display tokens `•••-••-6081` (SSN/ITIN), `••-•••0287` (EIN), `••••1234` (account), `••/••/••••` (DOB). Spreadsheet cells and search hits get the same tokens.
- **Golden-tested parameters live in repo files** (chapter 09 DEC-76 split); they are detector code, not firm content.
