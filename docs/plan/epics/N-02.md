### 2.2 Production versus fixture behaviour

- **Record mode is production from M8.** Before DocuSign is enabled for a firm, every envelope that reaches a client is either imported (record mode) or sent from the firm's own tool and recorded. SIG-01 renders record-mode envelopes with the same rows, drawer and evidence package (the provider column reads "Recorded").
- **DocuSign signing reaches real clients only after pen-test delta #2 is closed** (chapter 01 §1.2.3: delta #2, Aug 2 – Aug 11, 2027, covers "DocuSign hand-off"). Letters and consents flip at **M11 (Tue Aug 17)**; e-file authorizations flip at **M13 (Tue Aug 31)**. Synthetic firms and the canary run DocuSign on the demo account from S17.
- **Fixture-only states** are listed in §2.1 (SIG-01 b's 2848 row, SIG-02 c and d, POR-06 f). Each is hidden in production until its source epic registers the source; none is faked with live data.

## 6. Accrued Agent

**No agent capability is built in N-02, and N-02 makes no model call** (so no `ai_gateway` route, no prompt, no eval suite and no provider-terms model entry).

- **What the agent may do through N-02's API:** nothing in 2027. N-04's **Draft Form 2848…** is a human click that calls T-01's authorization request; code fills the form from CLI-05/T-01 data and the draft carries `drafted_by_kind = human` and the clicker (N-04 F2). `envelope.draft` and `letter.draft` keep a draft-only agent path (`drafted_by_kind = agent`, `drafted_via_run_id`, rendered "drafted … by Accrued Agent" with "Needs review") that is **reserved and unreachable in 2027**: the matrix row keeps `agent: allow` for draft-only use, but no registered capability calls it for an agency or client form, and a model-drafted IRS form (agency text under ADR P-25) waits until P-25 is enabled for the firm and that drafting capability has cleared its evals (DEC-79).
- **Gates (INV-1):** the agent principal is denied `envelope.send`, `envelope.remind`, `envelope.void`, `envelope.import_record`, `envelope.record_wet_signature`, `envelope.countersign`, `envelope_policy.manage`, `letter.approve`, `letter.send`, `letter.amend` and every portal action, at four layers: the matrix (generated I-AGENT-NEVER rows), the live-human check, the database CHECKs on `sent_by`/`voided_by`/`imported_by`/`approved_by`, and the banned-pattern rule. Envelope checks are computed by code, never judged by a model.
- **Not in scope:** agent-drafted letter clauses, envelope messages or reminder text (ADR P-25 ships off; DEC-79), and any agent read of e-file packets (TRI behind C19).
- **Evals:** none. T-01's and N-04's future agent drafters bring their own suites.
