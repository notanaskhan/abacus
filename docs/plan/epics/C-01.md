> Epic specification and task backlog for the plan of record dated Saturday 2026-10-17 (Sprint 0 starts Monday 2026-10-19). Chapter 01 is the plan of record for dates, owners and scope. Decision and ADR IDs are chapter 09's (DEC-nn, ADR P-nn, DF-nn); ADR numbers follow F-02's Decision Day erratum (`sections/epics/F-02.md` §4.6): only ADR-116…130 are fixed (for example P-04 = ADR-120, P-34 = ADR-122, P-35 = ADR-126, P-44 = ADR-128, P-05 = ADR-121, P-39 = ADR-124), and every other ADR number quoted below (for example ADR-133, ADR-136, ADR-145 or ADR-214) is provisional until `docs/adr/backlog.md` mints it at drafting; C-01-T01 checks by P-ID. **AY** = ayushkbhatia, **N** = notanaskhan. The CSV twin of §9 is `sections/epics/C-01.tasks.csv`; both are generated from one task list. Repo paths are relative to `github.com/notanaskhan/abacus` at `a42034c` and were checked in the clone; *(new)* marks a path that does not exist yet, and *(F-03)*, *(A-02)*, *(P-04)* and similar mark code an upstream epic delivers before C-01 needs it.
>
> **Short version.** C-01 gives Brightwater Hale's client accounting services (CAS) practice a monthly close on Accrued that **reads** the client's QuickBooks Online books and **never writes to them**. It ships, for the October 2028 closes (M20, Tue Oct 31, 2028):
> 1. **The close record and portfolio** (CLS-01, CLS-02): one close per client-month under a "Monthly close" engagement, a six-state status with server gates, and a run of the close plan's procedures, three at a time.
> 2. **The close plan and monthly intake** (CLS-09, CLS-03, POR-11): a versioned per-client plan that, on business day 1, publishes the month's requests to the portal, plus intake with screening, incorporation and transaction questions to the client.
> 3. **The code-first engine** (CLS-04, CLS-05, CLS-10): account tree and schedules, two-sided bank reconciliation traced to statement regions (OCR for scans), and dual-threshold flux. Every figure is computed by code (ADR-050).
> 4. **Review** (CLS-06): issues by severity, resolved only by people, with client questions sent in template wording.
> 5. **QBO live read with an hourly sync** inside Intuit's metering, on the connector A-02 built.
>
> **Read-only means read-only.** The Accrued Agent drafts, cites and waits. A person approves an entry (SHL-10), a person records it in QuickBooks outside Accrued, and the next sync ties the schedule ("Recorded in QuickBooks · JE 48214"). Posting through Accrued (W1, ADR P-16), adjustments approval UI (CLS-07), the FS package (CLS-08), the GL sync console (CLS-11), the tax hand-off (CLS-12) and 1099s (CLS-13) are **C-02**.

### 4.5 Temporal workflows, consumers and activities

All workflows start through `backend/src/abacus/kernel/dispatch.py` (ADR-071 bans `create_schedule` outside it, and `kernel.dispatch.schedule()` from ADR P-50 does not exist until W-03 in 2029). Recurring work therefore uses long-running workflows with durable timers and continue-as-new, following `backend/src/abacus/modules/agents/engagement_agent_workflow.py` and A-02's `ConnectionHealthWorkflow`. Workflow code reads time only through `kernel.clock`; calendars are read in activities. Payloads carry identifiers only. Every workflow has a replay history and uses `workflow.patched` for later changes (ADR-090).

- **`LedgerSyncWorkflow`** (`ledger_sync:<tenant>`, `connections`, red, work class `background`; started by `signal_with_start` when a close-enabled entity has a live ledger connection). Each hourly tick inside the firm's business hours (default 07:00–19:00 firm time; QC-5): `entities_due(tenant)` → per entity `cdc_changes(connection, since)` → `pull_datasets(connection, period, datasets)` → `record_snapshot` (new immutable snapshot, `ledger_snapshot.recorded`, `change_event.detected` per ADR-041) → `meter(tenant, calls)`. Failure codes cross to Temporal as class names only. `token_expired`/`invalid_grant` defers to A-02's health path (Needs reauth); `rate_limited` backs off per realm; `meter_budget_exhausted` pauses scheduled ticks. Continue-as-new every 24 ticks. A Sync now signal runs one entity at once.
- **`RequestPublishWorkflow`** (`close_requests:<tenant>:<close>`, `closes`, amber, `background`; started when a close is generated). It sleeps until `requests_publish_on` 09:00 firm time (BD1 computed in an activity from the practice calendar), then `pin_plan_version` → `generate_requests` (idempotent on close and template) → `publish_binder` → emits `close_requests.published`. A plan publish before BD1 signals the workflow to recompute nothing but the pin target.
- **Close runs** are P-10's `AgentRunWorkflow` (`agent_run:<tenant>:<run>`) with C-01's code plan provider registered through `register_run_step` (P-10-T39 pattern). Procedure executors are activities in `closes` (amber): `reconcile_statement`, `clear_third_party_sales`, `amortize_prepaid`, `depreciate_fixed_assets`, `recategorize_rules`, `roll_accruals`, each idempotent on `(run_id, step_seq, attempt)`. Concurrency 3 comes from `kernel/slots.py` and `kernel/work_class.py`. Decision cards hold a branch through P-10's `blocked_on_decision`; `decision.decided` resumes it. Model work runs as child runs of `close.agent` modes (`intake`, `bank_rec`, `aje`), never inside the deterministic executors.
- **`FluxExplain`** and **`ClosePlanDraft`** are `close.agent` runs in modes `flux` and `planner` on the same runtime; no new workflow type.
- **`CloseRecomputeConsumer`** (`closes`, outbox consumer on the `HumanGateProjector` pattern, idempotent on `event_id`): on `ledger_snapshot.recorded` for an entity with an unlocked close it recomputes reconciliations, schedules and flux sets as new versions, runs the `close_entry_recordings` matcher, and lets P-04's `StaleSignOffDetector` mark changed L1 sign-offs stale.
- **`CloseProcedureProjector`** (`closes`, consumer of `agent_run.status_changed` and step events): writes `close_procedures` and derives Not started → In progress.
- **Reminders** reuse P-06's `FollowUpCadence` with POR-20's cadence (every 7 days, at most 4, weekdays 9:00 recipient time; DEC-74).

## 6. Accrued Agent
