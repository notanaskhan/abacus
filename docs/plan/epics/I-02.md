# I-02 · Today brief

> Epic specification and task backlog. Chapter 01 is the plan of record for dates, owners and scope. Decision and ADR IDs are chapter 09's (DEC-nn, ADR P-nn, DF-nn); repo ADR numbers are F-02's reservations. Chapter 05's working IDs map as **AG-01 → ADR P-22, AG-02 → P-46, AG-03 → P-47, AG-05 → P-24, AG-06 → P-15, AG-07 → P-48, AG-15 → P-28, AG-16 → P-12** (chapter 09 §9.4.1). **N** = notanaskhan, **AY** = ayushkbhatia. The CSV twin of §9 is `sections/epics/I-02.tasks.csv`.
>
> **Short version.** Chapter 01 scopes I-02 as "Today brief per engagement: counts from code, narrative from a registered prompt with verified citations." I-02 builds exactly that on two P0 screens: **SHL-23**, the Today brief panel (470 px, docked or as a left drawer), and **HOME-05**, Home with the panel docked beside HOME-01.
>
> - **Code** builds everything that crosses engagements: the four Today count cells (the same C13 query that feeds HOME-01 and HOME-02, so 11 = 3 + 6 + 2 everywhere), a fact paragraph rendered from templates, the order of the engagement cards, the "Needs you first" rows, and every group (High risk, Due tomorrow, Ready for sign-off, Late, Needs attention, Running).
> - **The model** writes text one engagement at a time. A new capability, **`briefing.today` v1**, writes a short summary of one engagement for one viewer and a one-line "why" for each of that viewer's gates. Every sentence must carry a verified citation, and every number must be passed in by reference.
> - **Questions** typed into the panel run through W-02's `workbench.assistant` in read-only mode.
> - **"Assign open items"** prefills P-05's to-do drawer, and the person presses Create.
>
> I-02 adds no cross-engagement model call. The "portfolio agent" in ADR-063, build plan Phase 5 and chapter 05 A8 is a model-written cross-engagement lead and ranking, and it stays out of scope (Q1, Q6). The capability is `client_data: none`, so real firms see the code layer and the DF-04 "AI isn't available for real client data yet" line until a separate clearance decision (Q7).

### 3.3 Engagement briefings (model, per engagement · why lines, drill-in summary, risk line)

*As Daniel, I want the agent to explain each item in a line, with the source one click away.*

- *Given* any sentence in the output, *then*:
  - it carries at least one citation that passed its `evidence.register_citable` verifier (record_field, workpaper_cell, tax_form_line, request_item);
  - every numeric token equals a registered fact or a verified citation value (P-48 number provenance).

  If either fails, the validator repairs once. If it still fails, the briefing row is stored `unverified` and **no model text is displayed**; rows fall back to their HOME-01 context line (**INV-2**, DE-3).
- *Given* a gate that carries a decision-card recommendation (A-04's materiality, T-05's §754), *then* the why line may say "I recommend …" only by restating the recorded recommended option and its code values ("1.5% = $252,200"). ### 6.1 Capability `briefing.today` v1 (new; chapter 05 §5.3.3 registry row)

```yaml
id: briefing.today
version: 1
purpose: Explain one engagement's open gates to one viewer for today, citing every sentence.
shape: workflow                 # code collects facts, one model turn, code validates (no tools)
prompt: briefing.today@v1
tier: medium                    # claude-sonnet-5-5, pinned (chapter 05 §5.3.2)
escalation_tier: null
input_schema: EngagementBriefingFacts
output_schema: EngagementBriefing   # AgentBlocks p parts only; numbers as {fact} refs
tools: {}                        # ADR-049: none needed; facts come from code (ADR-050)
task_scope: [engagement.read, human_gate.read, decision.read, sign_off.read,
             request_item.read, agent_run.read]
limits: {max_output_tokens: 900, max_cost_usd: "0.10", max_steps: 1, max_seconds: 30}
plan: never
autonomy: propose                # proposes nothing; read-only narrative
data_classes: [confidential, tri]   # tri requires the C19 consent registration (fail closed)
untrusted_inputs: [facts.client_strings]
evaluation_suite: evals/briefing_today
work_class: interactive          # first open; staleness rebuilds re-class to background
essential: false
cheaper_tiers: []                # small tier only after a passing full suite (ADR-071)
routes: [bedrock, direct]
client_data: none                # synthetic only until a clearance decision (Q7)
```

**Inputs (`EngagementBriefingFacts`, built by T07 under the viewer's AgentContext):**
- Engagement: client short name; work items with label, kind, due, status code and optional `next_milestone`.
- Viewer: first name and role on the engagement.
- Gates: id, kind, title, due, state, `reserved_to_viewer`, `blocked_by` (ref, label, actor display), `blocks`, recommendation (option label and code values as facts), proposal (short title, proposer, awaited person).
- Runs: run number, state, started by.
- Attention items and optional dependents.
- A fact registry (`f1: 28,595.00` …) and candidate citations with their locators.

`deep_link`s never go to the model. Client strings are wrapped `<untrusted>`. TINs never appear (sealed, P-12). `data_subjects` carry TRI flags for the consent check.

**Output (`EngagementBriefing`):**
- `summary`: 1–3 sentences.
- `gates`: exactly one `{gate_id, why}` per supplied gate; `why` is one sentence of 160 characters or fewer.
- `risk_line`: one sentence, only when `facts.high_risk`.

Every sentence carries citation segments. Numbers appear only as `{fact}` segments.

**Validator (T08, code, after the model, before storage):**

| Rule | Behaviour |
|---|---|
| Gate coverage: one why per supplied gate, no unknown ids | Repair once, else `unverified` |
| Every sentence has ≥ 1 citation that passes its verifier (P-48) | Same |
| Number provenance: every numeric token is a fact or a verified citation value | Same |
| Recommendation fidelity: "recommend" only on gates with a recorded recommendation, and only its option | Same |
| Reserved verbs: no claim that the agent approved, signed, decided, assigned, sent, released or exported | Same |
| Scope: no entity name outside the engagement's fact set | Same |
| Style: no exclamation marks; banned words (to-do never "task"; no Fieldguide terms; never "Today's focus") | Same |
| Length limits | Truncation refused; repair |

Unverified rows are stored with their reasons for evaluation and are never displayed.

**Gates.** The agent recommends and explains, and nothing more:
- no tool can write;
- the matrix denies `briefing.*` to the agent principal;
- to-dos come only from a person pressing Create in SHL-17;
- decisions, sign-offs, approvals and sends happen in SHL-11, SHL-12, SIG-01 and TAX-09 by the named person (ADR-005, INV-1).
