## 3. Features & user stories

### 3.1 Capture corrections (WB-13e; T09)

*As Hannah Leclerc, when I correct an agent's output, I want the correction kept with a reason so that agents can later be improved, without anything changing until someone approves it.*

- **AC-1.** *Given* the Granite Peak FY2026 BH-FS-430 sheet, *when* Hannah edits item 27's agent value "Properly included" to "Properly excluded" with reason "Wrong period judgement" (SHL-19 or SHL-10 Approve with edits), *then* exactly one `corrections` row is written with the agent text, the corrected text, the reason code, Hannah as corrector and a NOT NULL `source_ref` (engagement, sheet, row), in the same unit of work as an audit event `correction.recorded`.
- **AC-2.** *Given* the same C3 decision event is delivered twice, *when* the subscriber runs, *then* no second row is written (UNIQUE `source_kind, source_id`).
- **AC-3.** *Given* `learning.enabled` is off for Brightwater Hale, *when* corrections arrive, *then* they are still captured (deterministic, data-boundary gate G-0 only), no proposal is generated, and WB-13 shows state **e**.
- **AC-4.** *Given* the backfill over existing C3 decisions, `agent_feedback` and screening review decisions, *when* it runs, *then* INS-02 and ADM-11 still read **206 of 3,410 = 6.0%** (DEC-96 one projection), and the backfill is idempotent.

### 6.2 Tools and context

- No new tools. `memory.proposer` is a single call whose inputs are assembled by code (corrections with agent and corrected text as untrusted, delimited blocks). The converter reads only its extraction.
- Firm-authored skill text is semi-trusted and enters only in the `skill` layer after the registered capability prompt (P-52/ADR-162); `ContextBuilder` v2 refuses a non-registry instructions layer (P-10-T21; today's `backend/src/abacus/ai_gateway/context.py` has the same rule).

### 6.3 Gates (INV-1)

### 7.2 Obligations

Notes, skills and seed text are firm wording or paraphrase; checklist items are references (ASC 855-10-50-1/-2), never codification text. The firm-wording check compares only with licensed text the firm holds.
- **§7216 (C19, P-12).** Learned-context items and evaluation cases derived from tax return information carry the TRI class; using them in an agent's context is gated per taxpayer by `consent_7216`; TRI-derived items cannot be Firm scope (CHECK; OQ-6 to counsel). Eval cases built from returns follow the same rule.
- **No cross-firm learning (ADR-053, ADR-067, D6).** Everything is tenant-scoped; cache keys include `tenant_id`; "Stays inside Brightwater Hale. Never shared with other firms." is a rule, not copy.
- **Firm-scoped evaluation (ADR-081).** Cases from reviewed rows stay in the firm and are readable only with `skill.evaluate`.
- **Agents propose, humans decide (ADR-005) and attribution (ADR-007).** Every approve, publish, resolve, subscribe and record is a human act with an audit event; agent drafts render "<person> via Agent" or, for system-initiated proposals, "Proposed by Accrued Agent", never as approver.
- **Retention (P-14).** Corrections and items follow their source's retention; a destroyed source retires the item and redacts the correction text; run records with uses keep the 7-year trace retention (ADM-04 E, locked).
- **Hostile content (ADR-052).** Corrections, workbooks and pasted text are untrusted, delimited and never executed as instructions.
- **Classification (ADR-031).** As in §4.2; every response model field carries `classified(...)`.
- **SQMS 1.** Published skills and notes with approver, date and evaluation record are evidence for the firm's intellectual-resources component; K-05 adds no SQMS screen.
- **Connectors** stay read-only; K-05 writes to no external system.
