## 1. Goal and user-visible outcome

**Goal.** Give every module two shared document services so that no screen has to invent its own:

1. **A deterministic renderer** that turns a firm template held in the database plus a frozen data snapshot into a byte-identical PDF (and DOCX where the design asks for "Open in Word"), stored as an immutable evidence version, with a DRAFT watermark until a named person approves it. This is contract **C11** (freeze S18).
2. **OCR, extraction and regions** inside the AWS boundary: scanned PDFs and phone photos get a word layer from Amazon Textract in the same sealed format P-03 built for text-layer PDFs, so masking, citations, search and the viewer work on them too; then code-only box maps read IRS notice headers, tax forms and bank-statement tables into `extracted_fields` and `extracted_tables` with a bounding box and a confidence for every value. This is an additive **C4 v1.1** on P-03's contract.

Chapter 01's scope note is binding: "deterministic PDF/DOCX renderer with templates held in the database (S17-S20, for letters and reports), then OCR and tax-form box extraction inside the AWS boundary (S28-S34, for notices, tax forms and bank statements)."

## 3. Features & user stories

Invariants are chapter 01's: **INV-1** the agent never decides; **INV-2** citations shown are verified; **INV-3** walls hold (404, no counts); **INV-4** portal scopes are isolated; **INV-5** attribution is correct. Seed clock: Mon 14 Sep 2026, 9:24 AM CT (E0) unless a state names another instant.

### F1 · Templates are database content (C11)

*As Grace Holloway, I want to load the firm's own letter wording without asking an engineer, so that a wording change never needs a deploy.*

- **AC1.1** *Given* a template bundle (JSON: family, name, layout key, DocBlock body, clause library, declared variables, synthetic sample data), *when* Grace calls `POST /v1/report-templates/import?dry_run=true`, *then* the response lists every error by path (`unknown_variable`, `unknown_layout`, `unknown_block`, `markup_not_allowed`, `clause_conflict`, `too_large`) and nothing is stored; with `dry_run=false` and no errors, a **draft** version is stored insert-only with its `content_sha256` and `report_template.imported` is audited naming Grace (INV-5).
- **AC1.2** *Given* a body containing HTML, CSS, a URL or a template expression outside `{"var": "<declared key>"}`, *then* import refuses with `markup_not_allowed`: firm templates are structured blocks, never markup, and the model never writes template content (ADR P-24).
- **AC1.3** *Given* a draft version, *when* Margaret publishes it with MFA in the window, *then* a `report_template_publications` row and `report_template.published` are written; *given* an agent, a worker or a client principal, *then* publication is refused by the matrix, by the `serving_request()` guard and by the absence of any agent path (INV-1).
- **AC1.4** *Given* a published version, *then* no route, migration or job changes it; a correction is a new version, and the previous version can be republished to roll back without a deploy.
- **AC1.5** *Given* the repo, *then* a CI scan finds no template wording in any migration, constant or fixture outside `abacus_tools/synthetic/scenarios/brightwater_hale/` (working agreement: content belongs in the database).

### F2 · Deterministic PDF render (ENG-04b, NOT-03a, AUD-23h)

*As Priya Raman, I want the letter I approve to be exactly the letter Tess signs, so that the firm can prove which terms were agreed.*

- **AC2.1** *Given* the same template version, data snapshot, clause states, section overrides and engine version, *when* the letter renders twice (two workflow runs, two containers), *then* the PDF bytes are identical: fixed `CreationDate`/`ModDate` from the snapshot's `as_of`, a document ID derived from `content_hash`, pinned fonts and engine, no locale or randomness (ADR-042, ADR P-19).
- **AC2.2 (ENG-04b, NOT-03a, POR-09a)** *Given* a draft render, *then* every page carries the DRAFT watermark (72 px, rgba(43,31,23,.06), per the S10 digest) and the page images SHL-08 and POR-09 serve show it; a draft never renders without it.

- **AC2.7 (ENG-04f)** *Given* a §7216 consent document, *then* it renders as its own document from the `consent_7216` layout, never as a clause of another document, at the layout's minimum type size (Rev. Proc. 2013-14 format rules as counsel confirms them, §11 OQ-7).

### F3 · Generated-document lifecycle: draft, final, out of date, locked

*As Hannah Leclerc, I want to know whether the report in front of me still matches the data, and who approved the version that went out.*

- **AC3.1** Status is computed, never stored mutable (DF-31 words): **Drafting** (a render job queued or running) · **Draft** (latest version is a draft) · **Approved** (latest version is final) · **Locked** (a lock event from the consumer, e.g. envelope completed or report released), with an **Out of date** overlay. *Given* AUD-23h, *then* the status is Drafting; *given* AUD-23i, Draft.
- **AC3.2** *Given* a consumer calls `reporting.api.render(…, mode="final", approval_ref=…)`, *then* P-11 resolves the reference through the kind's registered approval provider and renders only if the approval is by a human holding the consumer's approve action and its `content_hash` equals the draft version's `content_hash`; otherwise 422 `final_requires_approval` or 409 `approval_hash_mismatch`. The DB CHECK refuses a final version whose requester is not human (INV-1).
- **AC3.3** *Given* an agent-run context requests a render through a consumer service, *then* the version is a draft with `requested_by_kind=agent` and the run id; the audit line reads "<person> via Agent" (INV-5).
- **AC3.4 (AUD-23j, FSP-06c, ENG-04)** *Given* a registered source event (for example `engagement.status_changed` with a fee change, `statement_version.created`) whose re-resolved values differ from the snapshot, *then* within one relay cycle a `generated_document_events(kind=out_of_date)` row is written, `GET …/changes` lists the changed variables ("2 values changed"), and the consumer shows "Out of date · Update from data". An engine upgrade never marks a document out of date.
- **AC3.5** *Given* Hannah presses "Update from data", *when* `POST /v1/generated-documents/{id}/regenerate` runs, *then* version n+1 is a new draft; version n stays immutable; sign-offs registered on version n go stale through P-04's reviewable slot (`content_hash` changed). *Given* an agent or worker context, *then* regenerate is refused.
- **AC3.6 (ENG-04d, AUD-21d)** *Given* a locked document, *then* regenerate and final render answer 409 `document_locked`, and no code path re-renders it: the signed copy from DocuSign and the approved render stay the record.

### F7 · OCR inside the AWS boundary (SHL-08c/e, NOT-01c)

*As Kevin Osei, I want a photo of a notice to be readable and safe to share with the team, without anyone retyping it.*

- **AC7.6** *Given* a retry of the same page image (backfill, workflow retry), *then* the response cache keyed by page-image SHA-256 and API is used and Textract is not billed twice.
- **AC7.7** *Given* Textract text, *then* it is hostile content: it never reaches logs, metrics, Sentry or Temporal payloads (identifiers only), and agents see only the masked projection (ADR-052, ADR-031).
- **AC7.8** *Given* OCR of ≤ 20 pages, *then* p95 from upload to masked preview ≤ 3 minutes (chapter 10).

### 4.4 Renderer rules (code)

- **Engines:** WeasyPrint (PDF), python-docx (DOCX), openpyxl stays for XLSX (ADR-042 pattern). No headless Chromium, no pdf.js (DEC-16, DEC-44).
- **Isolation:** every render runs in `kernel.isolation.run_isolated` with renderer limits (`Limits(timeout_seconds=60, cpu_seconds=45, memory_bytes=1 GiB)`, inferred) in `worker-batch` (chapter 06 §1.6).
- **Fetcher:** a URL fetcher that refuses every scheme; assets resolve from an in-memory map keyed by `asset:<id>` (vendored fonts; firm letterhead and signature images stored as evidence and read through `evidence.api`).
- **Fonts:** Arimo, Gelasio and Geist Mono vendored in `reporting/fonts/` with their licences; a `FONTCONFIG_FILE` that lists only that directory; the image ships no other fonts, so a missing glyph fails the render (`missing_glyph`) instead of falling back.
- **Byte stability:** pinned engine and system-library versions in a digest-pinned image; `CreationDate`/`ModDate` = snapshot `as_of`; PDF identifier from `content_hash`; numbers and dates formatted by `reporting/format.py`, ported from F-05's `format.ts` with the same ≥ 60 golden cases; ZIP containers rebuilt with sorted entries and a fixed timestamp.
- **Watermark:** DRAFT on every page of a draft; SAMPLE for template previews; none only for `final`.
- **Field regions:** each variable occurrence is an element with a stable id; rects come from WeasyPrint's public page anchors refined against the rendered PDF's word boxes (pdfplumber). The S17 spike confirms the method; the fallback is text search for the value on the anchor's page (inferred).
- **PDF/A and tagging:** PDF/A-2b and tagged output with title and language where the pinned WeasyPrint supports them [verify]; not a blocking gate in v1.
- **Engine upgrades** change bytes: they need a golden re-baseline approved by both founders, never re-render a locked or final version, and never mark documents out of date.

### 4.5 OCR rules (code)

- **Input:** pages without a text layer and images. Images are normalised in the isolated child: EXIF orientation applied, HEIC decoded with `pillow-heif`, multi-page TIFF split, decompression-bomb limits as in `evidence/previews.py`. PDF pages rasterise with pypdfium2 at about 200 DPI, grey-scale, within Textract's synchronous size limit [verify].
- **Calls:** per page, synchronous, image bytes in the request (no S3 object handed to Textract, so ADR-104 client-side encryption is untouched): `DetectDocumentText` for every OCR page; `AnalyzeDocument FORMS` only for pages identified as a supported form; `AnalyzeDocument TABLES` only for statement pages in the `all` family. Throttling uses Temporal activity retries with backoff; deterministic refusals are non-retryable.
- **Normalisation:** Textract's normalised polygons become axis-aligned page-point boxes; words keep confidence; Textract `LINE` order gives reading order. The sealed raw response is kept beside the layer (same per-object key and retention) so a normaliser change does not re-bill (§11 OQ-6).
- **Region:** us-east-2 through an interface VPC endpoint; settings validation refuses non-US regions (R-35). In a DR failover to us-west-2, OCR runs only if Textract and the endpoint exist there [verify]; otherwise it pauses with `refused_reason=kill_switch` and pages stay `not_scannable`.
- **Cost:** the response cache by page-image SHA-256, FORMS only on identified pages, a per-tenant daily page cap (default 5,000 pages, inferred) and a budget alarm.

## 6. Accrued Agent

**Capabilities owned: none.** P-11 adds no agent, prompt, tool or model call. The rules it enforces for agents that touch its outputs:

- **Rendering:** an agent may cause only a draft render through a consumer workflow (`requested_by_kind=agent`, run id required by CHECK). It never renders a final, never regenerates through the route, never imports, previews or publishes a template, never locks (INV-1). Agent-drafted text reaches a document only as plain-text runs a person adopted in the consumer's editor; the model never writes template markup (ADR P-24). Model-drafted text to clients stays off by default (ADR P-25, DEC-79), which is the consumer's gate.
- **OCR and extraction:** code reads values; models judge (ADR-050). Agents receive OCR text only through `evidence.api.text_layer`'s masked projection and treat it as hostile (ADR-052). An agent cannot call `text/retry` and never sees a refused page's text.
- **Citations:** agent citations to OCR pages or extracted fields are ordinary C4 `document_text` citations with a bbox; P-03's verifier re-reads the OCR layer (INV-2).
