### 3.1 Work items and the engagement lifecycle (C1)

**Story 1.1.** As Priya Raman, I create Copperleaf's "2026 Close" and its 12 monthly closes, so a single contract holds many units of work.
- *Given* a `cas_monthly_close` engagement, *when* the close plan owner creates work items for 2026-01…2026-12 through `engagements.api.create_work_item`, *then* 12 `close` work items exist, each with a `closes` subtype row (`period` 'YYYY-MM'), and a 13th for an existing period answers 409 (ENG-02a shape).
- *Given* an `fs_audit` engagement, *when* a second `assurance` work item is created, *then* it answers 409 (`UNIQUE (tenant_id, engagement_id) WHERE kind='assurance'`).
- *Given* Thornbury's `tax_compliance` engagement, *when* four returns are created across the decedent and the estate, *then* each return carries its own `client_entity_id`.
- *Given* the migration has run, *then* every pre-existing engagement has exactly one `assurance` work item and one primary `engagement_entities` row, and every work-item row carries `(tenant_id, engagement_id, work_item_id)`.

**Story 1.2.** As Daniel Reyes (EP), I am the only person who can accept or decline an engagement, and the platform enforces the order.
- *Given* an engagement in `prospect`, *when* an agent or system principal calls the accept path, *then* it is denied at the matrix, at `require_live_human` and at the database check, and no `accepted` state is written (INV-1).
- *Given* an engagement in `prospect`, *when* someone tries to move it to `active`, *then* the API answers `409 {"detail":"illegal_transition"}` (DEC-39).
- *Given* any transition, *then* one `audit_events` row with the actor grammar "‹person›" and one `engagement.status_changed` outbox event are written in the same unit of work (INV-5).
- *Given* Bluestem is `accepted` with the letter not recorded, *then* the projection shows `gates: [{gate:"G3", met:false, blockers:[{type:"engagement_letter"}]}]` and publishing a client request answers `409 {"detail":"gate_unmet","facts":{"gate":"G3"}}` (ENG-02c, ENG-01b).

**Story 1.3.** As Priya, a non-attest CAS portal opens on the right gates.
- *Given* the per-type gate policy, *when* Copperleaf (non-attest, `cas_monthly_close`) has G1 and G3 met, *then* client data opens without G2; *given* Northwind (`ebp_audit`), *then* G1–G3 are all required (ENG-02b).
- *Given* a firm override, *when* it tries to make a gate looser than the platform default, *then* it is refused; stricter overrides are accepted.

**Story 3.1.** As Ana Cruz, the request board tells the truth about where each request is.

- *Given* `due_on` is past and the status is not `received` or `not_applicable`, *then* the API reports `overdue` as derived and never stores it (AUD-03g).

- *Given* the screener proposes `ready_for_review` or `needs_revision`, *then* the request becomes `uploaded` with the screening sub-state, the human accept/return path (REVIEW-001) is unchanged, and the agent never sets `received` or `returned` (INV-1).

- *Given* `tenant_entitlements`, *when* a route guarded by `require_entitlement("attest")` is called by a firm without Attest, *then* it answers 403 and the UI reason is `entitlement` (PLT-01b shape).
- *Given* `docs/architecture/feature-flags.yaml`, *then* a lint fails any `ff.*` module name (DEC-55); after the Dec 14–18 bundle no flag expires before Feb 1, 2027 and none is owned by "founder".

### 3.8 API conventions

**Story 8.1.** As an index screen, one list envelope serves every list.
- *Given* `GET /v1/work-items?kind=close&tile=in_progress`, *then* the response is `{items, next_cursor, total, total_capped, counts, facets}`, `counts` ignore the `tile` filter, cursors are opaque AES-GCM tokens with no readable client names, and errors carry identifier-only `facts`.

### 3.9 Module pre-registration and the router split

**Story 9.1.** As either founder, adding a module never touches a shared hot file.
- *Given* the per-module `registry.py` files, *when* a PR adds a table or router to `tax`, *then* it edits only `modules/tax/registry.py`; the generated `_matrix.py` and `_flags.py` are identical before and after the split.
- *Given* the 16 new packages, *then* import-linter enforces chapter 03 §2.3's graph, and unregistered work-item kinds, gates, scope kinds, consent checks and search projections fail closed.

**Story 9.2.** As AY, the firm router is split by area.
- *Given* `routes/firm/index.ts` and 14 area files in chapter 04 §2.2's nav order, *then* every current URL still resolves, guards run in `beforeLoad`, and each screen is its own lazy chunk.

### 3.10 Contract register

**Story 10.1.** As a consumer, a frozen contract cannot break under me.
- *Given* C1 v1 frozen, *when* a provider PR removes or renames a field, *then* the snapshot diff fails CI unless the PR ships C1 v2 with one sprint of overlap and both founders' approval (chapter 01 §1.3.2 step 5).
- *Given* a consumer's contract tests, *then* they run in the provider's CI and must stay green.
