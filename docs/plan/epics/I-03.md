## 1. Goal and user-visible outcome

Give Brightwater Hale's partners one place to see how the practice is running, measured only against the firm's own history, with every figure computed by code and every card stating its comparison basis. Give every professional a week of time already reconstructed from what they did in Accrued, which they confirm and push to practice management themselves. Accrued never becomes a billing or time system of record (D5), never shows another firm's figures (D6), and never lets the agent decide anything.

When I-03 ships (product code in production with the Thu May 17, 2029 promotion; flags on for the production canary tenant Tue May 22; J27 steps 1, 2a, 3, 4 and 5 and J17 A1–A2 walkable on staging and the canary by Fri May 25), with the demo clock at **Thu Oct 1, 2026**:

### 6.2 Tools and context

- **No tools.** One call over inputs assembled by code: metric facts with stable fact IDs and units; firm content labels (program and skill codes, request-type names) wrapped as delimited, untrusted text (ADR-052); the prefill hints for "Create to-do…" (the skill owner) are computed by code, never chosen by the model.
- **No client names, person names, client content or TRI** enter the prompt. The spec declares `data_classes: [internal, confidential]` without `tri`, so the §7216 condition (C19) does not apply; the gateway's boundary checks still run.
- **Output:** the closed `AgentBlocks` schema (P-24) with numbers by reference (`{{fact:<id>}}`); code substitutes the values, so the text cannot carry an invented number. Before storage, each suggestion is checked: exactly two cited facts, both present in the snapshot the page reads, every number in the text resolved from a cited fact, action key in the allow-list, no name tokens (deterministic check against the firm's people and clients).
- Stored as `suggestions` with `target_type = 'insights_tab'`, `field_key = 'efficiency_recommendation'`, `citation_ids` (C4 source kind `insight_fact`), linked to the run (`agent_run_id`).

### 6.3 Gates (INV-1)

The agent never: creates or assigns a to-do; dismisses or undoes a suggestion; edits, submits or recalls time; drafts or sends a follow-up from Insights; approves learned context; changes standard hours, adoption criteria or tolerances. ### 7.2 Obligations

- **ADR-024 and P-10.** Firm admins see metadata and counts only; content needs a place on the team; `security_admin` gets no Insights access (§11.2 OQ-5).
- **Walls (ADR-026, DEC-43).** Aggregates exclude walled clients per viewer with no counts; drills answer 404.
- **Employee activity data (DEC-96).** Activity events store references and durations, never content; calendar and mail are read only with the person's consent; nobody but the person sees a derived week, including managers, admins and platform support; retention is a P-14 record type (§11.2 OQ-8); counsel confirms that each firm's employee notice under state electronic-monitoring laws (for example New York Civil Rights Law §52-c) covers activity-derived time before `time.my_week` turns on for a real firm.
- **§7216.** Insights aggregates over tax engagements are used only inside the firm; the suggester receives no client names, content or TRI, so nothing is disclosed to the AI sub-processor; counsel confirms the internal-analytics use (§11.2 OQ-12).
- **Hostile content (ADR-052).** Practice report files are scanned (ClamAV), capped and parsed in isolation; client and label strings are delimited in prompts; every CSV export escapes formula prefixes.
- **Classification (ADR-031).** Every response field is tagged; fees, rates and client names are `confidential`.
- **Retention of write evidence.** W4 request and response evidence follows P-14 (ADR-138).
- **Agents propose, humans decide (ADR-005) and attribution (ADR-007).** Every create, dismiss, submit and recall is a human act with an audit event; suggestions read "Suggested by Accrued Agent".
