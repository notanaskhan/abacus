## 1. Goal and user-visible outcome

**Goal.** Give every engagement a conversation layer and a work layer that never become gates, and an immutable activity log that proves who did what. Concretely: (1) **comments v2** on polymorphic, version-pinned anchors, where Resolve and Reopen are append-only thread events and nothing is ever edited or deleted (ADR-109 as amended by ADR-209 / P-42); (2) **to-dos**, internal work assigned to a named person, never the agent, never a client and never a gate (glossary R6); (3) the **engagement activity log** (AUD-29), an engagement-scoped read over `audit_events` with the actor grammar "‹person›", "‹person› via Agent" and "Policy: ‹name vN›" (DEC-60). The epic is built entirely inside the 2028 busy-season window, so it ships dark, changes no live path, and leaves the live SPEC-032 request-item comments untouched until the post-window consolidation CL-1.

## 6. Accrued Agent

**Capabilities in this epic: none.** No model call is added, `ai_gateway` is untouched, and there are no eval suites or thresholds.

Rules P-05 enforces for the agent (INV-1):
- **Comments:** no model reads or writes comments (SPEC-032 non-goal; ADR-052 hostile content). `comment.*` actions are `agent: deny`; thread events carry `CHECK actor_kind = 'human'`.
- **To-dos:** the agent is never an assignee ("To have the agent do work, run it from the dock") and never creates, assigns, completes, reopens, moves or deletes a to-do (`agent: deny`, AC-19). A later agent tool (`todos.propose`, chapter 05 §5.3.4, W-02/I-02) may only *propose*; a named person accepts, and the resulting to-do is created by that person through `collaboration.api.create_todo`. P-05 provides that function and nothing else.
- **Activity:** AUD-29 only *displays* agent work as "‹initiator› via Agent" from `on_behalf_of_user_id` (chapter 05 §5.2.14); approvals, decisions and sign-offs are never attributed to Accrued Agent (AC-33). The Policy segment stays empty while P-08 is dormant.
