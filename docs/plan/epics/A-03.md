# A-03 · Sampling & TB mapping

Epic specification and task backlog, written Saturday 2026-10-17 for Sprint 0 starting Monday 2026-10-19. Chapter 01 is the plan of record for order, dates, owners and scope. Chapter 09 is the register of record for `DEC-nn`, `DF-nn` and `P-nn` IDs; this spec never cites chapter 03's or chapter 06's own P-34+ numbers. Repo ADR numbers are the reservations in F-02's schedule (`docs/adr/backlog.md`). **N** = notanaskhan, **AY** = ayushkbhatia. The machine-readable backlog is `sections/epics/A-03.tasks.csv`, and §9 mirrors it. Repo paths are relative to `github.com/notanaskhan/abacus` at `a42034c`; a trailing asterisk after a path (`path`\*) marks a file that does not exist yet.

> **Short version.** A-03 ships two deterministic engines and the two screens on top of them.
> 1. **The sampler** (`sampling`, amber, AY): a seeded, versioned, frozen selection library with golden tests and a frozen regression corpus (ADR P-57, DEC-81). A population comes from an uploaded file or from an imported or pulled general-ledger snapshot, and is proved complete by code-computed ties. The size comes from the firm's methodology table plus a statistical cross-check. The seed is drawn by the server and recorded. Every version is immutable. A manager approves, and one set of item requests then fans out to the client (POR-03) and third parties (POR-14). Screen **AUD-11**.
> 2. **Single-entity TB mapping** (`ledger`, red, N): a versioned grouping and FS-line taxonomy held as firm content in the database (DEC-66), one mapping set per TB of record (A-02's `trial_balances`: engagement × work item × entity × label × period), prior-year and number-range rules in code, human edits and confirmation, and staleness when a newer TB version is adopted. Contract **C9 v2** (taxonomy freeze S20). Screen **AUD-31** in its single-entity form (artboard f); the designed five-entity Harlow & Pike states and the TB-mapper agent follow in **A-09**.
>
> **Nothing in A-03 calls a model.** "The agent drawing" in AUD-11e is a code draw started by a person, and AUD-31's rule matches are code. Every write is `agent: deny` (INV-1).

### F1 · Sampler compute library (P-57; T04, golden by N in T09)

**US-1.1** As an engagement partner relying on a sample, I can re-perform it from its record.
- *Given* the frozen algorithm `2.3`, method `uniform_without_replacement`, the canonical Northwind census v2 (412 records, ordered by normalised record key) and seed `0x5E2A91`, *when* `select()` runs on any supported Python version, *then* it returns exactly the 25 designed participants in the designed order (Alicia Brennan NW-1184 … Fatima Qureshi NW-1224), and `items_hash` equals the corpus entry (AUD-11a card 3).
- *Given* method `threshold_random_stratified`, Granite Peak's 1,912 disbursements, thresholds ≥ $50,000 (all), $7,750–$49,999 (16 random), < $7,750 (none) and seed `0x7C31B4`, *then* strata count 24 / 1,102 / 786, the sample is 24 + 16 = 40 items totalling 3,698,700, and the value share renders 9.6% (AUD-11f).
- *Given* the selection code, *then* it calls only `random.Random(seed).getrandbits(32)` from the standard library; rejection sampling, the partial Fisher–Yates walk and ordering are Accrued code, so a change to `random.sample`, `shuffle` or `randrange` cannot move an item (DEC-81). A unit test fails if any other `random` member is referenced under `sampling/compute/`.
- *Given* an algorithm version exists in `SAMPLER_VERSIONS`, *then* its function body is frozen: the corpus test `(seed, population_hash, version) → items_hash` lives under `backend/tests/golden/sampling/corpus/`* (protected), and new behaviour ships only as a new version (chapter 10 §10.9.2).

**US-1.2** As a manager, the size and limits I see are computed, not typed.
- *Given* tolerable 10%, expected 0%, confidence 90%, *then* `attribute_size()` returns **22** (statistical cross-check) and `udl(0, 25, 0.90)` returns **8.8%** and `udl(2, 25, 0.90)` **19.9%** (exact binomial, `Decimal` with context precision 28, ROUND_HALF_UP to one decimal for display).
- *Given* $2,140 misstated in 25 items from a population of 412, *then* `project()` returns **35,267.20** (ratio estimate); the display rounding that yields "$35,300" is recorded as source conflict QA-3 and settled before the golden case is encoded, never "fixed" in a test.
- Hypothesis properties: strata partition the population (Σ counts = N, Σ amounts = total); selection is a subset without duplicates; same inputs give the same `inputs_hash` and items; size is monotonic in confidence and tolerable rate.
