## 1. Goal and user-visible outcome

**Goal.** Turn Workbench › Connect from the fixture specimen into a live, **honest** catalogue of the systems Accrued reads from and writes to. That means:

1. A data-driven catalogue, loaded as database rows and never as a commit. A tile shows **Available only when an adapter for it is built and registered**; everything else shows "Coming soon · Notify me" (DEC-46, DF-36).
2. Firm connections managed by IT/Security or the firm admin, personal "acting as you" connections for any user, and a read-only view of client-authorised connections. The client always authorises its own ledger in the portal (R1).
3. One detail drawer per integration that says how it authenticates, what Accrued may read, write and never do, its health and incidents, which agents depend on it and who can use it.
4. Connection health: a token expiry turns into "Needs reauth", notifies IT, and blocks dependent agent runs at admission until a person reconnects.

The epic builds on A-02's C20 framework and adds no new real connector. Each real connector remains its own epic with its own conformance suite (ADR-044).

### 2.2 In scope

- **Catalogue service** (red `integrations`): `effective_status` per viewer and firm, computed as listing status × registered adapter × environment × synthetic firm × kill switch × `published_at ≤ clock.now()`. Also: category and status counts in the P-36 envelope, search, enable-blocked reasons (prerequisite scope, role), viewer-relative status for personal tiles, Notify me (`integration_interest`), and the **catalogue import** service (dry-run diff, apply, import log) with a fan-out of `integration_available` notifications.
- **Connect, reconnect, disconnect:** firm-token and personal OAuth start and complete (hashed single-use state bound to user, scope and catalogue key, 10-minute expiry, PKCE; the `connections/connect.py` pattern), sealed secrets, firm-app enable for client-authorised items, typed-name disconnect with secret deletion and a best-effort remote revoke, personal revocation when a membership ends, and the firm-app disable for client-authorised items, which suspends the firm's client connections for that provider ("Needs reauth" in closes and POR-16).

## 6. Accrued Agent

**Capabilities: none. Tools: none. Model calls: none. Eval suites: none** (no prompt, no model, so ADR-076/081 add nothing).

W-01 changes how the runtime treats integrations, and that is tested as code (integration tests, not evals):
- Capability specs declare `requires_integrations` (P-22: specs live in code; firm agents may only narrow). The five CCH-dependent agents in the seed declare `cch-axcess-tax`.
- **Admission precondition:** a run whose spec requires an integration that is not `connected` for its scope (the firm install, or the acting person's personal install) fails at admission with a fixed code. It never retries silently. The failure is recorded against the integration's event so WB-11c can say "1 run failed".
- **Gates (INV-1):** the agent principal holds no `integration.*` action; no tool can connect, reconnect, disconnect or import. Agents read through integrations only as the person running them, and an agent's reads are limited to what that person can open (WB-11 "Who can use it").
- **No `write_capability.execute`** is introduced or granted; ADR-005 and ADR-040's read-only default hold.
