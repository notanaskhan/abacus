## 1. Goal and user-visible outcome

**Goal.** Give the firm one front door for documents that do not arrive against a request: a firm-wide Inbox fed by the client portal's "Upload something else" and by staff who log documents received through other channels (email, post, fax, in person), with code-first classification and flags, an agent that proposes a destination, and a triage sheet where a named person files, ignores or holds each attachment. Filing writes an immutable evidence version (or version n+1 that supersedes, never deletes, the earlier one) and moves the request through C5. Alongside it, a read-only Files browser shows every document the viewer may see, organised client › permanent file or year › engagement and work item › folder, including client-level files under ADR P-40. The data model is channel-agnostic, so **N-03** later adds the firm's `docs@` mailbox through Microsoft Graph without a schema change. The agent proposes; a named person decides (INV-1).

## 3. Features & user stories

Invariants asserted in every story's tests: **INV-1** no decision row has actor kind `agent` or `system`; **INV-2** every agent-set value carries a verified citation or reads "Uncited"; **INV-3** walls answer 404 and leak no count; **INV-4** a portal principal sees only its scopes; **INV-5** every state change writes an audit event with the actor grammar "‹person›", "‹person› via Agent" or "Accrued Agent".

**Story 3.1.1** As Grace Holloway, I log documents the firm received outside Accrued so they enter the same triage.

### 3.9 Cross-cutting invariants

- **INV-1:** `inbox.file`, `inbox.triage`, `inbox.match_sender`, `inbox.ask_client`, `inbox.log_intake` and `inbox_sender_rule.create` deny `agent` and `system`; the generated I-AGENT-NEVER test covers them; `triage_decisions` has `CHECK (actor_kind = 'human')`.
- **INV-2:** classification values from the matcher carry verified citations or read "Uncited"; every number on these screens (counts, totals, ties, differences) is computed by code (ADR-050).
- **INV-3:** walls answer 404 on threads, attachments, files, tree nodes and destinations; no count reveals a hidden item (DEC-43).
- **INV-4:** portal intake routes enforce `scope_only`; a principal reads and withdraws only its own uploads.
- **INV-5:** every decision, match, log, upload, withdrawal, read of content, reveal and download writes an audit event with the right actor grammar; matcher runs show "Accrued Agent" with `on_behalf_of` the client's relationship partner.
- **Client content is hostile:** attachment bytes, file names, portal notes, staff notes and (later) email bodies are untrusted; parsing runs in the isolated child (ADR-110), and the matcher treats them as `untrusted_inputs`.

**Compliance obligations.**
- **§7216 (P-12, C19):** documents a client gives a tax preparer are tax return information. - **Ethical walls (ADR-026, SPEC-002):** 404 everywhere, no hidden counts (DEC-43).
- **Immutability (ADR-004, ADR-034):** intake objects and evidence versions are write-once; supersede never deletes; the only erase is P-31's withdrawal of an unfiled client upload after 30 days unless held.

- **Hostile content (ADR-052/110):** parsing in the isolated child, byte sniffing, no macro execution, file names treated as text, no raw file rendered in the browser.
- **FTC Safeguards and the WISP:** per-object encryption, audited reads and downloads, `no-store` responses, MFA for TRI downloads; incidents through the incident register.
