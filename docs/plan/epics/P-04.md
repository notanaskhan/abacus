## 7. Integrations & compliance

- **External systems.** *CCH Axcess Tax* — file mode only, through T-01's file bridge (ADR P-18): imports arrive as `author_kind='import'` checkpoints; fixtures and E2E use T-01's fake CCH; P-04 never exports or transmits (requirement R-04). *AWS SES* — notification email through C16 database templates (P-01/R-01); template-based and sent by the system on human events only. - **§7216 and TRI.** Return fields, checkpoint diffs and field histories on `tax_return` targets carry the `tri` classification from the field owner; P-04 makes no model call, so gateway condition 6 (T-01) is unaffected; offshore users get TIN-bearing values masked by the API (`pii_kind` tags) and are denied any reveal (`not_offshore`).
- **Pub 1345 (DEC-85).** `checkpoint.approved` and import checkpoints carry amount deltas so T-01/N-02 can void a signed 8879 when total income or AGI moves by more than $50, or tax, withholding, refund or balance due by more than $14.
- **Need-to-know (ADR-024) and walls (ADR-026).** Firm admins see counts, never note bodies, rationales or field values; walled clients answer 404 everywhere, including `human_gates`.
- **SOC 2.** Every P-04 change is other-founder reviewed (CC8 change management); the review module joins the mutation-testing scope with a recorded floor.
