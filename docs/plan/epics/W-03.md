>
> **Short version.** W-02 gave Brightwater Hale conversational sessions. W-03 turns good sessions into reusable work, without letting anything run that a named person did not set up:
> 1. **A library of 28 agents published by Accrued** as platform database rows (two-person publish, never a commit). Each card is a mode and an instruction set over a capability spec that already lives in code (ADR P-22).
> 2. **The firm's own agents.** These are installed copies or agents created from a session, with an owner, sharing, inputs and defaults, versioned instructions, and a tool scope that can only narrow the capability.
> 3. **Schedules and agent triggers** on Temporal Schedules (ADR P-50) and K-04's trigger slot (ADR P-51). They run with the owner's live rights under a standing plan approval that a person recorded, and every write still waits for a named human.
> 4. **Run history per agent and firm-wide.** It shows tiles, what waits on whom, and a deterministic CSV.
> 5. **Saved prompts.** These are text that a person loads into any composer and sends. They never run, schedule, send or approve.
>
> W-03 has **six screens** (WB-04…WB-08, WB-12). It also builds the four saved-prompt artboards that W-02 deferred (WB-01 h, i; WB-02 g, h). Until **Fri Apr 20** everything merges dark behind default-off flags, migrations are expand-only, and nothing touches the live `agents` run path.

## 1. Goal and user-visible outcome

**Goal.** Let a firm reuse good agent work safely. It can install a published agent after reading exactly what that agent reads, drafts and never does. It can turn an ad-hoc session into its own agent, put it on a schedule or an event trigger, see every run and what waits on whom, and keep its best questions as saved prompts. The governance does not change. An agent never installs, publishes, approves, sends or decides. A scheduled run uses its owner's live rights under a plan approval that a named person recorded. A saved prompt is only text.

**Engineering outcome.**
- Library rows are platform data published through a two-person operator CLI on the reference-set pattern of K-02. A content change costs no deploy.
- Firm definitions are versioned, insert-only configuration resolved by `agents` at run start. Narrowing is checked in code at save time and at run time.
- Schedules use `kernel.dispatch.schedule()`. Agent triggers reuse K-04's matcher slot and `trigger_fires`.
- One picker contract serves every composer.

### F7 · Library publication (platform)

*As the Accrued operator team, we publish a new library version without a deploy, and nobody can publish alone.*

- **AC7.1.** `make library-publish --draft <package>` validates the package and writes drafts. It refuses a card in four cases: an unregistered capability or mode; tools outside the capability's allow-list; `requires_integrations` not in C20; a human-gate line that fails the directive lint.

- install, create, save, publish and share;

- pause, resume and archive;
- update to a new version;
