## 3. Features & user stories

Invariant references: **INV-1** the agent never decides · **INV-2** citations verified · **INV-3** walls hold · **INV-4** portal scopes isolated · **INV-5** attribution correct (chapter 01 §1.2). Platform-level analogues are stated where Q-01 is the enforcement point.

### F1 · Landing zone, residency and access (T01, T03, T04, T29)

**Story.** As N, I want every AWS resource to live in a governed account, in a US region, reachable by people only through short-lived, MFA-bound roles, so that residency and "no standing human access" are facts an auditor can test.

- *Given* the organisation root SCPs, *when* any principal in `staging` or `production` calls a regional API in a region other than us-east-2 or us-west-2, *then* it is denied; us-east-1 is allowed only for CloudFront, ACM for CloudFront, WAF (`CLOUDFRONT` scope), IAM, Organizations and Bedrock US Geo inference (P-55, R-35).
- *Given* Identity Center, *when* a founder signs in, *then* passkey or hardware-key MFA is required and the default permission set is `ReadOnly`; `iam:CreateUser` and `iam:CreateAccessKey` are denied everywhere by SCP.
- *Given* the `BreakGlassAdmin`, `abacus-retention-override` or `abacus-key-custodian` permission set, *when* it is assigned, *then* only the *other* founder can assign it, the assignment expires in ≤ 4 h, and CloudTrail → EventBridge pages both founders within 5 minutes (INV-5: a named human, never the author, approves elevated access).
- *Given* the Organizations AI-services opt-out policy at the root, *then* no AWS AI service may use Accrued content for service improvement; Bedrock model-invocation logging stays off in production (ADR-114).
- *Given* `infra/README.md`, *then* every one-time console step (Control Tower enrolment, Identity Center, opt-out policy) is recorded with date and operator, and nothing else is ever done in a console.
- *Given* Terraform, *when* any PR touches `infra/**`, *then* `infra.yml` runs `fmt -check`, `validate`, `tflint`, `trivy config` and a read-only `plan` per environment and comments a summary; no Claude Code session and no laptop ever holds apply credentials (`.claude/settings.json` denies `terraform apply/destroy`; `guard_bash.py` blocks `terraform state` and `aws --profile *prod`).

### F2 · Environments from Terraform (T07, T14, T15, T28, T29)

**Story.** As either founder, I want staging, production and a DR pilot light built from the same modules, so that what passes on staging is what runs in production (ADR-087/088).

- *Given* `infra/envs/{shared,staging,production,production-dr}`, *then* each environment is composed only from `infra/modules/*` with environment variables, and the plan-assertion suite (T24) proves: no public bucket; every bucket private, TLS-only, versioned and SSE-KMS with a platform key; Object Lock enabled on `abacus-<env>-evidence` (GOVERNANCE default mode, per-object retention) and `abacus-<env>-records` (Object Lock on, **no** default retention, so P-43 sets COMPLIANCE per object); RDS in `data` subnets with no public access, `rds.force_ssl=1`, `log_parameter_max_length=0` and `log_parameter_max_length_on_error=0`; security-group egress on 443 (plus 3310 to the scanner) only.
- *Given* the `app` subnets, *when* a task resolves a hostname that is not on the DNS Firewall allowlist, *then* resolution fails. Initial allowlist: Temporal Cloud, WorkOS, the Sentry US ingest, Better Stack heartbeats, `database.clamav.net`, and `api.anthropic.com` **in staging only**; AWS APIs resolve to VPC endpoints.
- *Given* production, *then* RDS is Multi-AZ `db.m7g.large` with 35-day PITR, cross-region automated backups to us-west-2 and a daily AWS Backup copy into the `audit` account vault under Vault Lock; evidence and records replicate to us-west-2 with retention replicated; the us-west-2 pilot light has services at zero tasks and KMS replicas.
- *Given* production before R2, *then* it holds only tenants with `firms.synthetic = true` (the canary); this is the chapter 06 §8.1 definition, and T35 asserts it.

### F3 · Production adapters (T05, T08, T09, T17)

**Story.** As the platform, I want each fail-closed adapter replaced by a real one that still fails closed, so that staging behaves like production and nothing silently degrades.

- **KMS (P1).** *Given* a tenant with a key, *when* evidence is sealed, *then* `KmsKeyService.wrap` calls KMS `Encrypt` on the per-object data key with encryption context `{"abacus:tenant": <tenant_id>, "abacus:purpose": "dek"}`; *when* a different tenant's context is used to unwrap, *then* KMS refuses and `DecryptionError` is raised (the AAD `abacus-evidence-v1|tenant|fingerprint|key_id` check stays). `key_id(tenant)` stays synchronous: it returns the deterministic alias `alias/abacus/tenant/<tenant_id>`; the resolved ARN is recorded on `firms.kms_key_arn` for drills and offboarding (P-65). *Given* any KMS error, *then* sealing and opening fail; there is no fallback to `LocalKeyService`, which keeps refusing outside local/test with a loopback S3 endpoint.
- **Payload keyring (P2).** *Given* `abacus/<env>/temporal/payload-keyring` in Secrets Manager, *then* the codec loads several key IDs and one current ID; a payload sealed under a retired-but-present ID still decodes; removing a key that histories still use is refused by the rotation runbook (RB-09).
- **SES (P3).** *Given* a message that passed `communications/scope.py` and the mechanical body check (no SSN, TIN, account number or tax amount), *when* it is sent, *then* `SesTransport` sends through the environment's configuration set with the firm's display name and Reply-To, and message tags carry only `tenant_id` and `message_id` (never an address); *given* a blocked message, *then* the SES client is never called.
- **ClamAV (P4, P-64).** *Given* an upload, *when* `scan(content)` runs on plaintext in the API before sealing (`evidence/uploads.py`), *then* `LocalScanner`'s archive-bomb checks run first and `ClamdScanner` streams `INSTREAM` to `scanner.abacus.internal:3310` (`StreamMaxLength 60M`, 30 s timeout); EICAR returns `malware`; any socket error, timeout or unexpected reply returns `unscannable`, which fails closed and shows the existing retryable state.
- **WorkOS (P5, P-54).** *Given* WorkOS staging, *when* a synthetic staff user signs in through hosted AuthKit on today's SPA PKCE flow, *then* `identity/tokens.py` verifies the token against WorkOS JWKS; a token minted by another WorkOS environment is rejected. AuthKit offers Microsoft, Google and email code, requires MFA for non-SSO users, and has no password method (DEC-22). The adapter port (`identity/workos.py`: discovery and JWKS, code exchange, user lookup, session revoke) is what P-01-T09 and P-08-T06 build on, and F-04-T27's fake conforms to it.
