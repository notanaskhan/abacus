# A-11 · Agentic audit: procedure session & pre-review

> Epic specification and task backlog, written Sunday 2026-10-18 for Sprint 0 starting Monday 2026-10-19. Task references `Tnn` in the text mean `A-11-Tnn`. Chapter 01 is the plan of record for dates, owners and scope. Chapter 09 is the register of record for `DEC-nn`, `DF-nn` and `P-nn` IDs; repo ADR numbers are F-02's reservations (chapter 05's AG-12 is chapter 09's **P-51**, reserved as **ADR-163**). **N** = notanaskhan, **AY** = ayushkbhatia. The CSV twin of §9 is `sections/epics/A-11.tasks.csv`. Repo paths are relative to `github.com/notanaskhan/abacus` at `a42034c` and were checked in the clone; paths marked *(new)* do not exist yet, and paths owned by an earlier epic are marked with that epic.
>
> **Short version.** A-11 is the last audit epic and the smallest. It adds no engine. It composes what K-03 (Sheets and agent columns), K-04 (Board, triggers, review package), P-10 (runtime v2), A-03 (sampler), A-04 (workpapers), P-04 (review notes) and P-06 (requests and screening) already ship into two P1 screens:
> 1. **AUD-36 Procedure session.** One substantive procedure, BH-FS-430 Search for unrecorded liabilities, run end to end by the `procedure.session` capability: a plan drawn from the firm's methodology, a population that code ties to the bank, strata and a seeded sample that code computes, one question to a person, a request drafted from the firm's template, a wait for the client, trigger-started testing on the sheet, a cited exception summary, an Expand testing offer that only a person decides, and a workpaper summary that only a person's sign-off adopts. Every one of the ten steps names the person it waits for.
> 2. **AUD-37 Pre-review.** The `review.pre_reviewer` capability checks a workpaper the way a reviewer would. Code runs the checks it can compute (stale sign-offs, report against workpaper, required evidence with zero citations); the model only judges whether a conclusion is supported. It lists findings by kind, each anchored to a cell with verified citations. Nothing becomes a review note until a reviewer creates one, and dismissals keep their reason.
>
> **The agent never decides.** It never approves the plan, answers the sampling question, sends the request, decides expansion, concludes a severity, creates or clears a review note, or signs. Both capabilities are model-backed, so they run on synthetic tenants only until each clears Bedrock evals, route parity and a per-firm shadow after the epic.

**Pre-review** (`review.pre_reviewer`, workflow shape, `background` class): `gather` (code: workpaper version and cells, cell citations, methodology steps, linked requests and their states, sign-offs, report links) → `deterministic_checks` (code: stale sign-offs by content hash, linked-value mismatches, required-evidence rows with zero citations) → `judge` (one structured model call per batch of ≤ 20 rows for conclusion support and wording; untrusted cell text wrapped) → `verify` (code: cell keys exist, citations pass verifiers, numbers are facts; failures dropped and counted) → `dedupe` (code: suppress dismissed identical findings and cells with open notes of the same kind) → `persist` (one UoW) → `complete`. Progress events "Checking citation n of m" come from `verify`.
