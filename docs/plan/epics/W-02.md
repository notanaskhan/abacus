# W-02 · Workbench sessions

> Epic specification and task backlog. Chapter 01 is the plan of record for dates, owners and scope. Decision and ADR IDs are chapter 09's (DEC-nn, ADR P-nn); repo ADR numbers are F-02's reservations. Chapter 05's working IDs map as **AG-01 → ADR P-22, AG-02 → P-46, AG-03 → P-47, AG-04 → P-23, AG-05 → P-24, AG-06 → P-15, AG-08 → P-35, AG-16 → P-12** (chapter 09 §9.4.1). **N** = notanaskhan, **AY** = ayushkbhatia. The CSV twin of §9 is `sections/epics/W-02.tasks.csv`.
>
> **Short version.** P-10 built the agent runtime: `converse()`, the tool registry (C17), the loop harness, runs, plans, questions, approval grants, the sessions core (`workbench_sessions`, `session_items`, `WorkbenchSessionWorkflow`) and SSE. F-07 built the T4 Workbench chat kit and locked TPL-04. P-09 built the run store, `AgentBlocks` and the WB-09 trace. P-04 built the ApprovalCard, proposals and the 10-second Undo. **W-02 turns those parts into the Workbench Sessions product** on three P0 screens:
> 1. **WB-01 Sessions**: the firm's conversational job surface and its universal run log ("via Agent" rows), with list filters, search, rename, delete and the locked thread.
> 2. **WB-02 New session**: a blank session, a context picker that lists only records the viewer can open, and a cited, read-only answer that ends "Nothing was written."
> 3. **WB-03 Run progress**: plan → gathering → working → ready for review, with the one file write waiting for the session owner and a 10-second Undo.
>
> W-02 also ships the capability **`workbench.assistant` v1** (loop, synthetic data only) with its eval suite, five new read and compute tools, the session list and context APIs, and the Brightwater Hale Workbench scenarios. Read-only answers ship first (S42); plans and writes follow behind a second flag (S44). Nothing here touches real client data: the capability stays `client_data: none`, and real-data clearance is a later, separate decision (§11 Q4).

## 1. Goal and user-visible outcome

**Goal.** Give every Brightwater Hale firm member a place to ask the Accrued Agent for work in plain language. The agent reads before it writes, asks one question when a request could mean two things, shows a plan before any bulk read, and leaves every write waiting for a named person. Every figure it shows is computed by code and cited. Every session doubles as the run log for that work, so scheduled, triggered and engagement runs appear in the same list, marked "via Agent".

**What Brightwater Hale people can do when W-02 ships** (staging and the synthetic canary, Fri Jul 21, 2028; demo clock at E0, Mon Sep 14, 2026):

### 5.5 Accessibility

- The thread is a `role="log"` live region (F-07). It announces completed items and run-state changes only (Plan ready — approve?, Running, Needs your answer, Ready for review, Failed), coalesced over 250 ms. Progress ticks ("120 of 241") are never announced.
- QuestionCard is a `radiogroup`: keys 1–9 select, Enter advances, Esc returns focus to the composer without answering (F-07-T06).
- The O1 picker traps focus, its tabs are a tablist, rows are checkboxes with the sub-line as description, "n selected" is announced, and Esc returns focus to the Paperclip chip. Chip × buttons are labelled "Remove <name> from context".
- The locked thread keeps focus where it was. Disabled controls explain why in a tooltip reachable by keyboard.
- The 10-second Undo is a server effect hold (DEC-24), so its time limit is fixed. The toast pauses its visual countdown on hover and focus, Undo is also offered in the collapsed approval line for the same window, and both are announced politely when they appear.
- Citation chips have accessible names ("Source 1: PayGrid Contribution Detail 2025.xlsx, pay date 12/26/2025"). The O4 preview is a labelled grid with sheet tabs as a tablist.
- Reduced motion: no word reveal, no cascade animation, no pulsing skeleton. Forced colors keep the amber dot, spinner and corner badge distinguishable by shape and text.
- axe: 0 serious or critical findings in every state and open overlay (T27).
