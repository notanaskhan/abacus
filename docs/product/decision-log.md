# Decision log

The register of every product and engineering decision for Accrued, one row per `DEC-nn`. The reasoning, options and owners live in [`docs/plan/09-decisions-adrs.md`](../plan/09-decisions-adrs.md) (section 9.3) and in chapter 01 section 1.9; this file records what was decided, when, and what binds the code.

## How to use this log

- **Find a decision.** Search this file by screen ID (for example `BND-01`), module or epic. The "blocks" column names what cannot be frozen until the row is decided.
- **Open rows.** Decide an open row in the session, taking the plan's proposed option (shown in the row), then change its status to `decided`, set the date, and name the artefact that binds the code. Do not wait for a meeting; `docs/plan/AMENDMENT-solo.md` item 7 applies.
- **New decisions.** Append a new `DEC-nn` row at the end, using the next free number. Never renumber or delete a row.
- **Artefact.** The ADR, SPEC, config file or task that makes the decision binding in code. "ADR for P-nn" means the ADR is not drafted yet; its number comes from [`docs/adr/backlog.md`](../adr/backlog.md).
- **Money.** Rows record the option, never an amount. Amounts are set in the vault.
- **Status.** `decided`, `open`, or `n/a, solo edition` (two-founder governance and the release train, voided by the solo amendment).

Dates are ISO. For open rows the date is the decide-by date from the plan.
